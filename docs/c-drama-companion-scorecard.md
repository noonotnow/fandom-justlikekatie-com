## Windows and denominators

- **T0:** not set. The live route/unauthorized-response checks above were completed on 2026-09-28; an authorized operator must still retrieve a valid production report and verify the production Stripe endpoint receives `invoice.paid` before setting T0. Record the UTC timestamp and concrete calendar ranges here after those checks. No 30/60/90-day countdown starts from a merge, a deploy preview, or unauthorized probes alone.
- **Baseline:** the 30 UTC days immediately before T0 (`[T0 − 30 days, T0)`); unavailable for new pilot events. Record existing membership only if sourced from an approved production report.
- **Day 30:** `[T0, T0 + 30 days)`; **Day 60:** `[T0 + 30 days, T0 + 60 days)`; **Day 90:** `[T0 + 60 days, T0 + 90 days)`. These are nonoverlapping reporting windows, not cumulative cohorts. The admin report accepts half-open UTC `from`/`to` dates with a maximum of 31 days, so run each window separately once closed. For 7-/30-day returns wait for the complete follow-up period; currently not measured.
- **Opt-in numerator:** report `byPath.*.added` (first stored successful consent) within the window. `updated` tracks repeat/changed consent and is not a new person; `removed` counts actual stored-record removals, not unknown-address requests. `currentActiveConsents` is a *report-time snapshot*, not the end-of-window count. Never subtract suppressed cells or interpret null as zero.
- **Visitor denominator:** `qualifiedSessionVisits` is a privacy-safe *session proxy*: after 10 visible seconds the browser sends one event per path per tab session; the server excludes recognized crawler user agents and signed-in admin sessions. No visitor ID, email, or token is sent in the analytics payload or stored in its event. This is not unique people: cleared session storage, multiple tabs/devices, unrecognized bots and anonymous staff can inflate it, and blocked scripts can undercount it. Report it as qualified session visits only after live verification; unique human readers and true visitor-to-opt-in rates remain **not measured**. `pathEventRequests` is a count of accepted page-event writes, not a denominator. `membershipViews` and `checkoutStarts` are also request counts, not people or payments.
- **Paid outcome:** `firstPaidCollectorInvoices` counts distinct processed Stripe `invoice.paid` webhook events for first subscription invoices with positive amount paid and the configured Collector price. It includes all Collector acquisition, not just companion traffic. It is only reportable after the production webhook subscription to `invoice.paid` and live report storage are verified. Paid users, refunded/net revenue, and path-attributed purchases: **not measured**. A `membership_activated` browser event is not proof of payment.
- **Reporting access:** use the admin-authenticated Netlify `/.netlify/functions/companion-report?from=YYYY-MM-DD&to=YYYY-MM-DD` endpoint, never local or Replit analytics as production evidence. It returns only suppressed counts (cells below 10 are null), no addresses, identifiers, tokens, or raw events; verify its live authorization before querying. Do not copy subscriber Blobs or raw billing records into analytics. If a store or webhook is unavailable, mark its metric “not measured,” never zero. Keep this scorecard focused on companion outcomes; SEO visibility belongs to its separate reviews.

## Reporting contract

- **Qualified visit:** use the bounded, visible-ten-second `companion_qualified_view` session proxy rather than `companion_path_view` raw requests. It excludes recognized bots and authenticated staff, but anonymous staff/QA must still be excluded operationally; never claim it proves unique human readers. Use only authorized production aggregates with filters and denominators documented. If unavailable, mark “not measured”; never substitute local tests.
- **Interest:** the server stores separately checked email consent and the selected path; no mail is sent by signup. The address is not ownership-verified, so verify it before any later mailing. A client `companion_interest_click` is a directional interaction, **not** a confirmed opt-in. The server writes a bounded change receipt after successful stored consent or removal, with only path, action and time; the private subscriber record remains the source of current state. Unsubscribe removes the record.
- **Return and use:** derive cohort 7-/30-day return and saves from an approved aggregate source and an agreed privacy-safe visitor definition. Cross-device attribution and guide completion are not yet instrumented: “not measured,” not zero.
- **Paid intent:** membership view and checkout-start events can carry a same-tab pilot path. A checkout-start is not payment. Do not claim path-attributed purchases until billing confirmation is joined through an authorized, privacy-safe server-side method. Record confirmed purchase totals separately if attribution is unavailable.
- **Interviews:** invite 15–20 engaged fans if recruitment is possible, record method, consent, sample size, existing alternatives, and what they already pay for. Not yet recruited.
- **Decision rule:** 3–5% visitor-to-opt-in is a provisional planning trigger, not a benchmark. If qualified traffic is too low or reporting is unavailable, extend or narrow the test rather than choose a winner. Review editorial hours and support load alongside utility and paid intent. Annual plans, dossiers, and staffed events require a separate go/no-go review.

Incremental 90-day capacity estimate: engineering **18–26 person-days**, editorial/rights **19–26**, research/operations **6–9**, excluding daily publishing and existing work. Lean capacity (one engineering day and six editorial hours weekly) means entry paths, interviews, at most 1–2 reviewed boards and one note; defer maps, events, and new paid products.
