The algorithm’s definition of **Event** is too literal and too dependent on a single source/editorial cluster.

## “Event” should mean visual continuity—not merely a literal event

An Event-style board can be any coherent visual world:

- **Literal Event** — one ceremony, premiere, livestream, or press appearance
- **Editorial Set** — one magazine shoot or campaign
- **Costume Study** — the same costume across different scenes and angles
- **Character Study** — one character across a coherent role/look
- **Scene Family** — one setting, sequence, episode, or visual motif
- **Styling Moment** — the same hair, makeup, silhouette, or accessory across appearances

The audience experience remains:

> **“No, look closer.”**
> 

The sameness is the subject. It does not matter whether all nine images came from one website or one photographer.

Even from this mediocre broad query, I can see potential arguments around:

- **White/gray austere immortal Liu Xueyi**
- **Red-and-black fur-trimmed menace**
- **Pale ceremonial robes**
- Potential character-specific clusters once the results are mapped back to roles and scenes

The system appears to have detected **three fragmented event families**, but it failed to understand that images from different pages and scenes can belong to the **same costume or character continuity family**.

That is the actual algorithm problem.

## The curation pool is also too cramped

It shouldn’t:

1. Rank queries.
2. Take only a tiny handful of winning query batches.
3. Demand that one preassembled family already contains nine images.
4. Declare Event impossible.

It should:

1. Search the entire approved query ladder.
2. Pool all viable candidates within a bounded but larger limit.
3. Deduplicate exact copies.
4. Extract continuity signals across queries and sources.
5. Cluster by:
    - Character/drama
    - Exact costume or styling
    - Color and silhouette
    - Setting
    - Editorial/event metadata
    - Scene or promotional family
6. Build **multiple candidate boards from each promising cluster**.
7. Score the finished boards—not merely whether a preexisting cluster happened to contain nine items.

## Controlled similarity must not be mistaken for duplication

For a costume-study board:

- Same costume: **desired**
- Same character: **desired**
- Different angle/expression/action/background: **desired**
- Exact crop or essentially identical frame: **reject**
- Nine indistinguishable headshots: **weak**
- Nine scenes that reveal the same visual identity: **excellent**

A strong costume board might use:

- 6–7 unmistakable anchor images in the same costume
- 2–3 contextual or detail images
- Variation in distance, pose, expression, and scene lighting

That is a deliberate mood board, not failed variety.

## The preflight should propose several boards

Instead of only:

- Strongest Event
- Strongest Compiled

It should be able to generate:

- **Event A — Costume study**
- **Event B — Character continuity**
- **Event C — Editorial/source set**
- **Compiled A — Best range**
- **Compiled B — Vibe-first range**

Then select the strongest Event and Compiled for blinded comparison—but let us inspect the runners-up and understand what material exists.
